The rule

In words

  1. The plan counts days from launch: creators accepted by 7, first order delivered by 21, first draft in by 35, first post live by 42, last posts by 56.
  2. Each step is about the first creator to get there, because the tile is about first content.
  3. Early: when the first order, the first draft or the first post lands early, "first content expected" moves earlier by the same number of days. Creators accepting early does not move it.
  4. Late: the date is the later of two things: what the last step implies, and today plus the time the remaining steps need (21 days after an order arrives, 7 after a draft). So it slides later only when it has to. Proposed
  5. The tag shows when the week on the tile is earlier than the week promised at launch. There is no opposite tag.
  6. The crossed-out date shows with the tag, only for good news.
  7. The tail: early never moves an end date. Late moves the ends later by the same number of days.
  8. After the first post the tile states the fact and counts posts. After the last one it says so.
# the plan, in days from launch
PLAN   = { accepted: 7, delivered: 21, first_draft: 35, first_post: 42, last_post: 56 }
REMAIN = { accepted: 35, delivered: 21, first_draft: 7, first_post: 0 }   # to first content

# reached_on(step) = the day the FIRST creator got there
latest = last of [delivered, first_draft] reached        # accepted never pulls the date earlier
base   = latest ? reached_on(latest) + REMAIN[latest]
                : [42, reached_on(:accepted) + 35].max   # a slow match can only push later
floor  = today + REMAIN[next step not yet reached]       # what is still physically possible

first_content_expected = first_post_reached ? reached_on(:first_post)
                                            : [base, floor].max
early      = monday(first_content_expected) < monday(launch + 42)   # tag + crossed-out date
late_by    = [first_content_expected - 42, 0].max

phase.starts = reached ? reached_on : first_content_expected - REMAIN_AT_START
phase.ends   = planned_end + late_by        # early never moves an end; late moves all of them

What Nisarg needs from the data

Four dates per campaignThe first creator accepted, the first order delivered, the first draft submitted, the first post live.
Two countsCreators on the campaign, posts live.
Three flagsWho ships (Shopify or the brand), who reviews drafts (Benable or the brand), and whether creators are waiting for the brand's approval. They only choose between a grey line and an amber one.
Where it showsThe tile, the full timeline inside it, and the campaign card on the overview. One computed value feeds all three.

What does not change

The campaign's month name stays frozen at launch. "Week 4 of 8" stays a calendar count. Local and gift card campaigns have no tile.

Hold the plan, for comparison

The RULE switch in the live tile has a second setting: "Hold the plan when late". That is the Sep 8 position: good news moves the date, a late step changes nothing. Try it with "Shipping is slow" and drag past Oct 25 to see the tile promise a week that has gone.
