The rule

The plan is the dates the tile already draws. The change: when the first creator reaches a step early, the start of what follows moves earlier. The ends do not move, because the other creators are still on the usual clock.

In words

  1. Three moments can move the date, each with a planned day counted from launch: first product arrived (day 21), first draft in (day 35), first post live (day 42).
  2. Each is about the first creator to get there. The tile is about first content, and first content comes from whoever is furthest ahead.
  3. Creators accepting early does not move it. Nothing has shipped yet, so it is too soon to promise.
  4. How far ahead? Planned day minus the day it really happened, for the latest of the three.
  5. The new date = launch + 42 days, minus the days ahead. Still shown as "week of" the Monday.
  6. Only the front moves. A phase starts earlier; it ends where the plan put it. The campaign's last day stays launch + 56. Julia · Oct 5
  7. Never later than the plan. If the latest moment is late, days ahead counts as zero and the original date stays.
  8. Once the first post is live, the tile shows the fact ("First content went live · Oct 15") and stops forecasting.
# on top of the existing rule: first_content_expected_on = launch_date + 42 days
PLAN_DAY = { first_delivery: 21, first_draft: 35, first_post: 42 }

# reached_on(m) = the day the FIRST creator got there
latest = last of the three reached
ahead  = PLAN_DAY[latest] - (reached_on(latest) - launch_date)   # days; negative = late
shift  = [ahead, 0].max                                          # never later than the plan

first_content_expected_on = first_post_reached ? reached_on(:first_post)
                                               : launch_date + 42 - shift

# phase windows in the full timeline
phase.starts_on = reached ? reached_on(phase) : planned_start - shift   # the front moves
phase.ends_on   = planned_end                                           # the tail never does
campaign_ends_on = launch_date + 56                                     # unchanged
# recomputed only when one of the three moments happens, never day by day

What others do

Familiar patterns, recalled rather than captured for this study, so treat them as direction and not evidence.

Parcel trackingOne date, replaced when it changes, with a short status next to it ("arriving early", "delivery date updated"). The closest match to version C.
Flight statusScheduled time struck through, new time beside it, and a word: early or delayed. The struck-through plan is what makes the gain readable.
Ride and food deliveryA countdown that updates constantly. It works for minutes, where nobody plans around the number. A campaign is planned in weeks.
Project tools"Ahead of schedule" and "behind schedule" badges on a fixed plan. The badge pair is the trap in version D.
